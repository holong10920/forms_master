# Python → Go contract matrix

All Admin operations now terminate in the Go BFF at browser origin `http://localhost:4180`; there is no Python RPC proxy. The existing editor's `/api/<operation>` contracts are retained where practical. All POST operations require the one Go session, exact trusted Origin, and its CSRF verifier. Permission and site membership are re-read server-side. Bodies/responses below are JSON unless stated otherwise. Errors retain `{code,retryable?,diagnostics?}`; authentication middleware uses the Go `{error}` contract with 401/403.

Go module files divide responsibilities within one process: auth/users/session persistence, studio forms/sites, reviews/workflow, policy/authorization, preview/public, releases, submissions/outbox and audit. The public/Preview listeners are security origins owned by the same Go business backend, not competing business implementations.

The engine ports the Python executable IR semantics; schema lowering remains in the retained TS compiler. Fixtures compare 236 TS/Go/Python evaluation cases plus submission cases. `compileRelease` defaults to its legacy Python test oracle for old P0, but the unified compiler adapter sets the fixed Go authority and invokes `var/go-auth/engine-oracle`. No arbitrary executable or shell string is accepted from a request.

Immutable legacy Store Selector locks still identify the approved Python source digest. Those source bytes remain a read-only provenance input; the Go implementation performs the synthetic query/validation. Rewriting existing locks/releases merely to rename that provenance would break release identity and is intentionally avoided.
